# PaneCue v0.1 Release Build

Status: **v0.1.0 locally qualified; public binary distribution deferred.** The
source milestone is qualified on macOS 26 Apple Silicon. Apple Developer
Program enrollment, Developer ID signing, and notarization can be enabled
later without changing the application code or release format.

## Qualified source milestone

- Version: `0.1.0`
- Platform: macOS 26 on Apple Silicon
- Evidence: the automated acceptance gate and recorded packaged macOS smoke
  matrix
- Deferred: macOS 14, macOS 15, Intel, Developer ID signing, notarization, and
  public binary distribution

The `v0.1.0` Git tag records this source milestone. An ad-hoc DMG may be used
for local validation only and must not be published as a production download.

PaneCue public builds are distributed as a hardened-runtime, Developer ID
signed, notarized DMG. Signing credentials stay in the developer Keychain and
are never stored in the repository.

## One-time setup

1. Install a `Developer ID Application` certificate through the Apple
   Developer account.
2. Store App Store Connect notarization credentials in Keychain:

   ```sh
   xcrun notarytool store-credentials "PaneCue-notary"
   ```

3. Confirm that the certificate is available:

   ```sh
   security find-identity -v -p codesigning
   ```

## Build the distributable DMG

Run the automated acceptance gate first, then build and notarize:

```sh
./scripts/run_v01_acceptance.sh
./scripts/build_release_dmg.sh \
  --identity "Developer ID Application: YOUR NAME (TEAMID)" \
  --notary-profile "PaneCue-notary"
```

The command signs `PaneCue.app` with the hardened runtime, creates and signs a
versioned DMG, waits for Apple notarization, staples the ticket, validates the
result, and prints its SHA-256 checksum. The artifact is written to
`build/release/`.

## Local packaging check

Before a Developer ID certificate is available, exercise the same packaging
path without publishing the result:

```sh
./scripts/build_release_dmg.sh --adhoc
```

An ad-hoc artifact is only for local smoke testing. It must not be uploaded to
GitHub Releases or presented as a public beta.

## Release rule

Do not publish if the acceptance gate, `codesign`, notarization, stapling, DMG
verification, or the documented macOS smoke matrix fails. Increment
`CFBundleVersion` for every artifact distributed to testers.
