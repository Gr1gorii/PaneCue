# PaneCue v0.2 Public Beta Release

Status: **Frozen; release engineering not yet qualified**

Version: **0.2.0**

Starting development build: **14**

Supported platform: **macOS 26 on Apple Silicon**

PaneCue v0.2 is distributed through GitHub Releases as a Developer ID signed,
Hardened Runtime enabled, notarized, and stapled arm64 DMG. An ad-hoc build is
for local development only and must never be published as a beta.

## External prerequisite

The release owner must:

1. enroll in the Apple Developer Program;
2. issue a `Developer ID Application` certificate;
3. keep the private key in the release-owner Keychain with a protected backup;
4. store notarization credentials in Keychain with `notarytool`;
5. keep Developer ID, notarization, and Sparkle private keys out of Git,
   project files, logs, task files, and CI artifacts.

Apple enrollment and identity verification are user-owned external actions.
Source development can proceed in parallel, but no public RC may ship before
they complete.

## Release artifact contract

The final GitHub Release contains:

- `PaneCue-0.2.0-buildN-arm64.dmg`;
- `SHA256SUMS`;
- source tag;
- supported-platform statement;
- installation and Accessibility guide;
- privacy and update-network behavior;
- known limitations;
- Apple Shortcuts and Raycast integration guide;
- changelog and support/issue link.

The final GA DMG must be byte-identical to the final tested RC DMG.

## Stable bundle contract

The public `PaneCue.app`:

- contains only stable executable targets;
- contains no Cloud Voice, OpenAI, Chrome video, ScreenCaptureKit, Ollama, or
  Suggestions implementation;
- contains no Screen Recording or Apple Events usage description;
- opens no network connection for arrangement processing;
- includes Sparkle as its only network-capable stable subsystem;
- requests Accessibility only for window inventory/control;
- requests Microphone and Speech only for explicit offline voice;
- never exposes an external Apply route.

The separately named experimental application is not included in the public
v0.2 DMG.

## Signing contract

Every executable, framework, XPC service, and Sparkle helper is signed from
the inside out. After signing:

- no bundle file is changed;
- Hardened Runtime and secure timestamp are present;
- `get-task-allow` is absent;
- entitlements match the reviewed allowlist;
- App Sandbox remains intentionally disabled;
- signing identity remains stable between RCs and GA.

The signing identity change from the v0.1 ad-hoc build may cause macOS to ask
the user to grant Accessibility again. Release notes and onboarding must
explain this once. Future builds must preserve the production signing identity.

## Update contract

PaneCue uses Sparkle 2:

- `Check for Updates…` is always available manually;
- automatic checks are off until the user opts in;
- the appcast uses HTTPS;
- update archives use a dedicated EdDSA key;
- system profiling is disabled;
- the UI distinguishes local arrangement processing from update-network
  access;
- RC1 to RC2 update must pass on a qualified Mac before GA.

The Sparkle signing key is separate from Developer ID and notarization
credentials.

## Release workflow

The protected tag or manually approved release job performs:

```text
checkout exact commit
→ full tests
→ build stable and experimental targets
→ binary-separation checks
→ package stable app
→ sign nested code and app
→ create and sign DMG
→ notarize
→ staple
→ verify Gatekeeper and distribution policy
→ calculate SHA-256
→ archive dSYM and notary log
→ create a draft GitHub Release
```

Release credentials are unavailable to pull requests and forks.

## Candidate sequence

```text
v0.2.0-rc.1
→ 5–10 external testers
→ fixes
→ v0.2.0-rc.2
→ seven days without P0/P1
→ promote the exact tested artifact
→ v0.2.0
```

Any code change after RC2 creates a new build and restarts the relevant gate.
GA is not rebuilt from the same source if doing so would change the tested
artifact.

## Clean-machine qualification

On a qualified macOS 26 Apple Silicon Mac, test:

- Safari download with quarantine;
- offline Gatekeeper launch;
- drag installation to `/Applications`;
- standard non-admin user;
- Accessibility denied, granted, and revoked;
- Accessibility migration from the ad-hoc v0.1 identity;
- complete core arrangement with the network unavailable;
- Settings, Cues, and Journal migration;
- RC1 to RC2 Sparkle update;
- uninstall and reinstall.

Required final checks:

```sh
xcrun notarytool history --keychain-profile "PaneCue-notary"
xcrun stapler validate "/path/to/PaneCue.app"
spctl --assess --type execute --verbose=4 "/path/to/PaneCue.app"
syspolicy_check distribution "/path/to/PaneCue.app"
hdiutil verify "/path/to/PaneCue-0.2.0-buildN-arm64.dmg"
shasum -a 256 "/path/to/PaneCue-0.2.0-buildN-arm64.dmg"
```

## Do not publish when

- Developer ID, Hardened Runtime, notarization, or stapling is missing;
- Gatekeeper or clean-machine installation fails;
- stable binary separation fails;
- any external request can Apply;
- an ambiguity can be resolved silently;
- update verification fails;
- an open P0 or P1 remains;
- the artifact differs from the final tested RC;
- release notes imply support for macOS 14, macOS 15, Intel, or more than one
  external display.
