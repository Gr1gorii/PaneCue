# PaneCue v0.2 Scope

Status: **Frozen**

Release target: **0.2.0 public beta**

Supported platform: **macOS 26 on Apple Silicon**

Distribution: **GitHub Releases through a Developer ID signed, notarized, and
stapled DMG**

## Included product capabilities

| Capability | Release requirement |
|---|---|
| Quick Cue | `Option-Space` opens a compact command panel over the current application |
| Text command | Russian and English commands create a local Preview |
| Optional offline voice | Explicit recording, editable transcript, and confirmation before Preview |
| Compact Preview | Show every slot, target display, geometry summary, resolution state, and match reason |
| Ambiguity Resolver | Require the user to choose when more than one window matches |
| Full editor handoff | Open the same draft in the existing Arrange editor |
| Explicit Apply | Only a direct action in PaneCue may move windows |
| Result and Undo | Report every target truthfully and keep Undo beside the result |
| Apply Journal | Persist at most five privacy-safe Apply transactions |
| Restart recovery | Offer restoration after PaneCue restarts when original windows remain available |
| PaneCue Links | Support `panecue://show`, `panecue://preview`, and `panecue://cue` |
| Shortcuts and Raycast | Document safe Preview-only invocation |
| Existing Arrange and Cues | Preserve the qualified v0.1 behavior |
| One external display | Preserve the qualified Sidecar contract |
| Stable updates | Sparkle 2 with HTTPS, EdDSA signatures, manual checks, and opt-in automatic checks |

## Included architecture and release work

- one Arrangement Coordinator shared by Arrange, Quick Cue, PaneCue Links, and
  saved Cues;
- explicit target-resolution states: resolved, ambiguous, missing, and
  unsupported;
- versioned, atomic, bounded Apply Journal storage;
- physical separation of stable and experimental SwiftPM targets;
- stable binary separation checks;
- safe ownership-based Chrome and Ollama cleanup in the experimental build;
- release identity `0.2.0`, starting with build `14`;
- Developer ID Application signing and Hardened Runtime;
- notarization, stapling, Gatekeeper verification, and clean-machine testing;
- Sparkle 2 update packaging;
- release CI and GitHub Release publication;
- RC1 to RC2 update testing and a seven-day release gate without P0/P1 defects.

## Stable binary exclusions

The stable `PaneCue` executable must not depend on or contain object code for:

- Cloud Voice or OpenAI endpoints;
- Chrome video control or AppleScript video automation;
- FaceTime or ScreenCaptureKit capture;
- Vision-based browser cropping;
- Ollama, Qwen, or FunctionGemma;
- Suggestions/Auto Mode.

The stable bundle must not contain Screen Recording or Apple Events usage
descriptions. Experimental code may exist only in a separately built and
identified executable.

## Deferred beyond v0.2

- automatic Apply or unattended window movement;
- Suggestions/Auto Mode in the stable build;
- Cloud Voice and BYOK;
- Chrome video, FaceTime video, ScreenCaptureKit, and Vision crop;
- Ollama, Qwen, FunctionGemma, and other alternative local-model experiments;
- Spaces and calendar automation;
- sync, accounts, teams, or centralized management;
- more than one external display;
- macOS 14 and macOS 15 runtime qualification;
- Intel or universal distribution;
- native App Intents;
- CLI;
- payments, subscriptions, and licensing enforcement;
- full workspace or document recovery after a Mac reboot;
- Mac App Store distribution.

Deferred capabilities do not block v0.2 and must not appear in stable
onboarding, navigation, permissions, or release claims.

## Permission contract

| Permission | v0.2 stable behavior |
|---|---|
| Accessibility | Requested immediately before the first window inventory or control operation |
| Microphone | Optional and requested only after the user explicitly starts voice input |
| Speech Recognition | Optional and requested only for offline speech |
| Screen Recording | Absent |
| Apple Events | Absent |
| Input Monitoring | Absent; tap-versus-hold hotkey behavior is deferred |

## Network contract

- Parsing, Preview, target selection, Apply, Undo, Journal, and recovery make
  zero network requests.
- Manual update checks may access the documented HTTPS appcast.
- Automatic update checks require explicit opt-in.
- Sparkle system profiling is disabled.
- Stable diagnostics and logs do not transmit telemetry.

## Data contract

The Apply Journal may store:

- transaction identifier and timestamp;
- application bundle identifier;
- ephemeral process/window identifier;
- original frame and display signature;
- safe visibility/minimized state;
- result and completion state.

It must not store:

- command text or transcript;
- window title;
- document path or URL;
- screenshot or window content;
- API key or update credential.

## Scope-change rule

A capability can enter v0.2 only when it is required to:

1. complete the frozen Quick Cue demonstration;
2. remove a P0 or P1 safety, privacy, recovery, or distribution risk;
3. satisfy a frozen public-release gate; and
4. preserve explicit Apply and the offline core.

Any other capability moves to v0.3 or later through a recorded decision.
