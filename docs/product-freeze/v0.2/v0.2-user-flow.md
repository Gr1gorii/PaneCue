# PaneCue v0.2 User Flow

Status: **Frozen**

## Primary entry points

- **Quick Cue** — global `Option-Space` command, local Preview, Apply, and Undo.
- **Arrange** — full command and plan editor.
- **Cues** — saved layouts and import/export.
- **Settings** — permissions, shortcuts, updates, Journal history,
  personalization, and diagnostics.
- **PaneCue Links** — external show or Preview requests that always surface
  PaneCue UI.

PaneCue opens on Arrange when launched normally. Quick Cue does not require the
main window to be visible.

## Primary happy path

1. The user works in any application.
2. The user presses `Option-Space`.
3. Quick Cue appears on the active display with focus in the command field.
4. The user enters a Russian or English command.
5. Enter parses the command locally and creates a compact Preview.
6. Preview shows every slot, target display, geometry summary, resolution
   state, and match reason.
7. If every required target is resolved, the user may:
   - press Apply;
   - open the full editor;
   - cancel.
8. Apply revalidates every target and persists a pending Journal transaction
   before the first window mutation.
9. PaneCue moves only valid, visible Preview targets and shows a truthful
   per-window result.
10. Undo is available beside the result.

Enter never creates a Preview and applies it in the same action.

## Ambiguous target flow

1. Preview identifies a slot with multiple matching windows.
2. The slot displays `Needs selection`, and Apply is disabled.
3. PaneCue shows the application icon, application name, and a local-only
   differentiator for each candidate.
4. The user chooses one candidate using the keyboard, VoiceOver, or pointer.
5. The slot changes to `Selected by you`.
6. PaneCue revalidates the exact selected window before Apply.
7. If the candidate disappears or the set changes, the slot returns to
   ambiguous or missing. PaneCue never silently chooses another window.

Window titles may be displayed locally for selection, but they are not logged,
diagnosed, journaled, or transmitted.

## Optional offline voice flow

1. The microphone control is available only after successful text onboarding.
2. The user explicitly presses the microphone control.
3. PaneCue requests Microphone and Speech Recognition only when needed.
4. PaneCue records locally while showing an active recording state.
5. The transcript is displayed and remains editable.
6. The user confirms the transcript.
7. PaneCue creates a Preview; it does not Apply.

Denied or revoked voice permissions leave text input fully usable. PaneCue
never listens in the background.

## PaneCue Links flow

Supported routes:

```text
panecue://show
panecue://preview?text=<percent-encoded-command>
panecue://cue?id=<cue-uuid>
```

1. Shortcuts, Raycast, Terminal, or a browser opens a supported route.
2. PaneCue validates length, encoding, route, and parameters.
3. PaneCue opens visible UI and marks the request as external.
4. A valid request creates a Preview through the same Arrangement Coordinator.
5. The user explicitly presses Apply inside PaneCue.

Unknown, malformed, repeated, or rate-limited requests produce No Action.
There is no `panecue://apply` route, and an external caller cannot bypass
Preview or confirmation.

## Restart recovery flow

1. Before window mutation, PaneCue atomically records a pending transaction.
2. If PaneCue exits before completion, the pending transaction remains.
3. On the next PaneCue launch, the app offers `Restore previous layout`.
4. Nothing is restored automatically.
5. PaneCue matches only still-running, unambiguous original windows.
6. The user explicitly confirms Restore.
7. Available windows are restored; ambiguous or missing windows are skipped
   with a truthful partial result.

v0.2 does not promise recovery after a Mac reboot and does not reopen
documents, URLs, or applications as part of Journal recovery.

## Cancellation and concurrency

- `Esc` closes Quick Cue without Apply or side effects.
- Closing any PaneCue UI does not trigger Apply.
- A new command cancels obsolete parsing work.
- PaneCue executes at most one Apply or Restore transaction at a time.
- An external request does not interrupt an active Apply.
- Repeated Quick Cue invocation moves the panel to the current active display.
- Quick Cue does not retain command history after the panel closes.

## Failure behavior

| Situation | Required behavior |
|---|---|
| Accessibility unavailable | Explain the need, open the correct settings pane, and move no window |
| Global hotkey conflict | Show the conflict in Settings and keep Arrange usable |
| Command not understood | No Action with a safe clarification |
| Several windows match | Require explicit selection before Apply |
| Selected window disappears | Return the slot to missing or ambiguous |
| Target becomes full-screen, minimized, or unchangeable | Leave it unchanged and show the reason |
| External display disconnects | Skip only its assigned targets; never fall back silently |
| Apply partly succeeds | Show every outcome and offer Rollback for changed windows |
| Journal is corrupt or truncated | Ignore safely, explain locally, and never crash |
| Recovery target is ambiguous or missing | Skip it and report a partial result |
| Microphone or speech permission denied | Keep text Quick Cue available |
| Network unavailable | Keep the complete core flow available; only updates fail |
| Malformed or unsupported deep link | No Action and no window mutation |

## Required end-to-end cases

1. Quick Cue from Safari, Finder, Terminal, and VS Code.
2. Russian and English text commands.
3. Optional Russian and English offline voice with editable transcript.
4. Candidate chooser with two matching browser windows.
5. Candidate closes or changes before Apply.
6. Compact Preview to full editor without losing the draft.
7. Apply, Undo, partial Apply, and Rollback.
8. Crash/relaunch recovery with complete and partial restoration.
9. Sidecar connected and disconnected after Preview.
10. Deep links from Terminal, Safari, Shortcuts, and Raycast.
11. Malformed, unknown, oversized, and repeated deep links.
12. Accessibility denied, granted, and revoked.
13. Sparkle manual check and opt-in automatic check.
14. Signed update from RC1 to RC2.
