# PaneCue v0.1 User Flow

Status: **Frozen**

## Primary navigation

- **Arrange** — command, Preview, editing, Apply, result, and Undo.
- **Cues** — saved layouts and import/export.
- **Settings** — permissions, processing mode, personalization, and
  diagnostics.

The application opens on Arrange. There is no separate Overview in v0.1.

UI vocabulary:

| Current prototype term | v0.1 term |
|---|---|
| Command Lab | Arrange |
| Custom Scenarios | Cues |
| Auto Mode | Suggestions Beta |
| Scenario 2.0 | Remove from user-facing text |
| Workspace Plan | Plan or Preview |
| Restore Previous Layout | Undo |

## First-run happy path

1. The user installs and opens PaneCue.
2. Arrange shows a short explanation and one text command field.
3. When the user first tries to inventory or move windows, PaneCue explains
   Accessibility access and opens the correct System Settings pane.
4. After permission is granted, the user enters:

   > VS Code большой слева, Safari справа, Terminal маленький снизу.

5. PaneCue displays a Preview containing all three selected windows and their
   intended positions.
6. The user can:
   - press Apply;
   - resize or move a window directly;
   - add, remove, or replace a target;
   - type a follow-up such as “Terminal поменьше”.
7. The user presses Apply.
8. PaneCue revalidates the targets, then moves only the windows visible in the
   Preview.
9. PaneCue shows the result and an adjacent Undo action.
10. The user can Undo or save the approved plan as a Cue.

## Time and permission targets

- First Preview within two minutes of installation.
- First applied layout within three minutes of installation.
- One required permission for the text flow: Accessibility.
- No API key, account, scenario creation, microphone, speech recognition, or
  screen recording during text onboarding.
- Undo is visible in the same result area as the successful Apply.

## Apply contract

Immediately before Apply, PaneCue must:

1. refresh the inventory of target windows;
2. detect closed, replaced, ambiguous, or newly full-screen targets;
3. update or block the plan instead of silently choosing a different window;
4. snapshot every selected window it can change;
5. make no changes to windows absent from Preview.

After Apply, PaneCue reports each target as:

- moved;
- unchanged;
- skipped with reason; or
- failed with reason.

If only part of the plan succeeds, PaneCue shows a partial result and offers
Rollback for the windows it changed.

## Failure behavior

| Situation | Required behavior |
|---|---|
| Accessibility is unavailable | Explain why it is needed and open the Accessibility pane |
| A target application is not running | Offer to launch it in Preview; launch only after Apply |
| Several windows match | Ask the user to select or show all candidates in Preview |
| A window cannot be resized or moved | Leave it unchanged and show the reason |
| A window closes after Preview | Recalculate or block Apply and explain the change |
| Only some windows move | Show a per-window partial result and offer Rollback |
| The command is not understood | Produce No Action and suggest safe clarifications |
| The network is unavailable | Continue the complete local text flow |
| A target is full-screen | Ask before leaving full-screen; never do it silently |
| A minimized target is selected | Handle only after the minimized-window test matrix passes; otherwise explain the limitation |
| Undo cannot restore one window | Restore available windows and report the unavailable target without claiming full success |

## Required end-to-end cases

1. New install → Accessibility → first Preview → Apply → Undo.
2. Russian command with three windows.
3. English command with three windows.
4. Follow-up resize before Apply.
5. Mouse resize before Apply.
6. Ambiguous target selection.
7. Closed application offered for launch.
8. Target closes between Preview and Apply.
9. One non-resizable target produces a partial result and Rollback.
10. Complete offline flow with network disabled.
11. Save as Cue, relaunch, and apply the saved Cue.
12. Import and export a Cue.
