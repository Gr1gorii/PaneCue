## Issues found and resolved during the pass

- Natural layout descriptions without an action verb previously fell through
  to a generic two-window preset.
- Russian plain size language did not select the requested dominant window.
- The initial three-window preset gave Notes and the compact Terminal equal
  heights. A 75/25 horizontal split also proved too narrow for Notes on real
  hardware. The final layout keeps a one-third secondary column and expresses
  the compact request with a 75/25 vertical split inside that column.
- Dashboard action closures lost main-actor isolation and could trigger a
  Swift concurrency runtime trap during Apply.
- A fresh build centered its first main window on whichever display was active,
  which could split test builds across displays. A main window without a saved
  frame now opens on the primary display; an existing saved position is still
  respected.

Regression tests were added for the command cases, and all dashboard actions
that reach AppKit or `AppDelegate` are now explicitly main-actor isolated.
The Cue lifecycle smoke used temporary records and a temporary archive; both
records were removed after the saved state was verified. The application
lifecycle smoke likewise used a temporary Cue and test windows; all temporary
state was removed after exact frame checks and Rollback.
The full-screen and minimized pass likewise used a temporary Cue and temporary
app copies. Both copies began on the built-in primary display, their actual
window frames and on-screen state were checked after Apply and Rollback, and
the Cue and copies were removed afterward.

## Qualification state

This pass qualifies the core local Arrange → Preview → Apply → Undo journey,
including a complete three-window arrangement, on one macOS 26 Apple Silicon
configuration. It does not close the full v0.1 support matrix; the remaining
manual cases above and the other target macOS versions still require recorded
runs.
